# SG-003 — Unchecked arithmetic on token amounts

| | |
|---|---|
| **Name** | `unchecked-arithmetic` |
| **Default severity** | warning (info when `overflow-checks = true`) |
| **Confidence** | high / medium / low (per finding) |
| **Tags** | security, arithmetic, overflow |

## What it detects

In files belonging to a Soroban crate (the package depends on `soroban-sdk`, or the file references
`soroban_sdk`):

1. **Plain arithmetic** — `+`, `-`, `*`, `+=`, `-=`, `*=` where an operand looks like a token
   amount: its name (variable, field, called function or method) contains a word such as
   `amount`, `balance`, `supply`, `fee`, `price`, `allowance`, `reward`, `stake`, `debt`,
   `collateral`, `shares`, `liquidity`, `reserve`, `deposit`, `principal`, `interest`, `payout`.
2. **Lossy casts** — `as` casts of such a value to any integer type other than `i128`
   (`amount as u64`, `amount as u128`).

Severity and confidence for arithmetic depend on the release profile of the workspace
(`[profile.release] overflow-checks` in the workspace root `Cargo.toml`):

| `overflow-checks` | Behaviour on overflow | Severity | Confidence |
|---|---|---|---|
| not set / `false` | wraps silently | warning | high |
| `true` | transaction panics | info | low |
| no manifest found | unknown | warning | medium |

Casts are reported at medium confidence — `as` never checks, regardless of profile — unless the
value is range-checked in a condition in the same function (`if amount > 0 { amount as u128 }`).

Not reported:

* `checked_*`, `saturating_*`, `wrapping_*` method calls (they are not operators);
* subtractions guarded by a comparison of the same operands in an `if` condition or assertion,
  e.g. `if balance < amount { panic!() } … balance - amount`;
* expressions whose operands are only literals and `SCREAMING_CASE` constants;
* arithmetic on non-amount names (`i + 1`, `len * 2`).

Each arithmetic expression is reported once (`a + b - c` is one finding).

## Why it matters

Release builds wrap on overflow unless `overflow-checks = true`. A wrapped balance can mint tokens
out of thin air or turn an underflow into a huge balance. Even with overflow checks, a cast such as
`amount as u64` truncates silently and `negative_i128 as u128` becomes an enormous value.

## Example

```rust
let new_balance = balance + amount;   // ⚠ SG-003
let reward = stake * rate / BPS;      // ⚠ SG-003
let out = reward as u64;              // ⚠ SG-003 (lossy cast)
```

Fixed:

```rust
let new_balance = balance.checked_add(amount).ok_or(Error::Overflow)?;
let reward = stake.checked_mul(rate).ok_or(Error::Overflow)? / BPS;
let out = u64::try_from(reward).map_err(|_| Error::Overflow)?;
```

and in the workspace `Cargo.toml`:

```toml
[profile.release]
overflow-checks = true
```

## Known limitations

* No type inference: operands are recognised by name only. `x + y` on balances named `x`/`y` is
  missed; `fee_count + 1` is reported.
* Guard detection is purely syntactic (same operand names compared somewhere in the function).
