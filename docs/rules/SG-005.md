# SG-005 — Initializer can be called more than once

| | |
|---|---|
| **Name** | `unprotected-initializer` |
| **Default severity** | error |
| **Confidence** | high |
| **Tags** | security, initialization, access-control |

## What it detects

An exported function named like an initializer — `init`, `initialize`, `initialise`,
or starting with `init_` / `initialize_` / `initialise_` (plus any names in `initializer-names`) —
that writes contract storage (directly or through helpers) but has **no "already initialized"
guard**.

A guard is any of the following, in the function or in a helper it calls:

* a storage `has(..)` call, e.g. `if env.storage().instance().has(&DataKey::Admin) { panic!() }`;
* a storage `get(..)` used in an `if` / `match` / `while` condition, a `let … else`, or an
  assertion macro, e.g. `assert!(storage.get::<_, bool>(&Init).is_none())`;
* a local variable initialized from storage and used in a condition;
* a call to a storage-reading helper inside a condition, e.g. `if has_administrator(&e) { … }`.

`__constructor` is never reported: the host runs it exactly once at deployment.

## Why it matters

Exported functions are callable by anyone at any time. An unguarded `initialize` lets an attacker
call it again after deployment to install themselves as admin, swap the token address, or change
fees. Deploying and initializing in separate transactions also lets an attacker front-run the first
call.

## Example

```rust
pub fn initialize(env: Env, admin: Address, token: Address) {   // ⚠ SG-005
    env.storage().instance().set(&DataKey::Admin, &admin);
    env.storage().instance().set(&DataKey::Token, &token);
}
```

Fixed (preferred, protocol 22+):

```rust
pub fn __constructor(env: Env, admin: Address, token: Address) {
    env.storage().instance().set(&DataKey::Admin, &admin);
    env.storage().instance().set(&DataKey::Token, &token);
}
```

Fixed (guarded initializer):

```rust
pub fn initialize(env: Env, admin: Address, token: Address) -> Result<(), Error> {
    if env.storage().instance().has(&DataKey::Admin) {
        return Err(Error::AlreadyInitialized);
    }
    admin.require_auth();
    env.storage().instance().set(&DataKey::Admin, &admin);
    env.storage().instance().set(&DataKey::Token, &token);
    Ok(())
}
```

## Known limitations

* The rule checks that a guard *exists*, not that it reads the same key the function writes.
* Initializers with unusual names are missed unless added to `initializer-names`.
* Front-running of a guarded initializer is not reported; deploy and initialize atomically (or use
  `__constructor`).

## Options

```toml
[rules.SG-005.options]

```
