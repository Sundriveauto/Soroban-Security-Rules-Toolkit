# SG-006 — Signed amount not checked for negative values

| | |
|---|---|
| **Name** | `negative-amount` |
| **Default severity** | warning (info in admin-only functions) |
| **Confidence** | medium (low in admin-only functions) |
| **Tags** | security, input-validation, arithmetic |

## What it detects

An exported contract function with an `i128` parameter that ends up in **contract storage** —
written directly (`set(&key, &amount)`, `set(&key, &(debt - amount))`) or passed to a crate helper
that writes storage (`write_balance(&e, &to, balance + amount)`) — when the parameter is never
compared with zero.

A parameter counts as checked when the function, or a helper it is passed to, does any of:

* compares it with `0` (`amount < 0`, `amount <= 0`, `0 < amount`, …), including inside
  `assert!`-style macros;
* calls `is_negative()`, `is_positive()` or `signum()` on it;
* passes it, or a value computed from it, as an argument of an external token call (`transfer`,
  `transfer_from`, `mint`, `burn`, `burn_from`, `clawback`, `approve`). Token contracts reject
  negative amounts, so the whole invocation fails.

When only a stored admin (or another non-parameter address) authorizes the function, the finding
is reported as **info** with low confidence: a negative value there is a configuration mistake
rather than an attack.

`__constructor` and `__check_auth` are skipped.

## Why it matters

Soroban token amounts are `i128` and can be negative. Internal accounting that trusts the sign
inverts: a negative mint lowers someone's balance, a negative repayment increases a debt, a
negative fee pays the caller, a negative stake withdraws.

## Example

```rust
pub fn repay(env: Env, borrower: Address, amount: i128) {
    borrower.require_auth();
    let debt: i128 = env.storage().persistent().get(&DataKey::Debt(borrower.clone())).unwrap_or(0);
    // ⚠ SG-006: amount = -1000 increases the debt
    env.storage().persistent().set(&DataKey::Debt(borrower), &(debt - amount));
}
```

Fixed:

```rust
pub fn repay(env: Env, borrower: Address, amount: i128) {
    borrower.require_auth();
    if amount <= 0 {
        panic_with_error!(&env, Error::InvalidAmount);
    }
    // …
}
```

## Known limitations

* **False positives:** parameters that are legitimately signed (deltas, adjustments). List them
  under `ignore-params` or suppress with a reason.
* **False negatives:** checks against a non-zero bound (`amount >= MIN_DEPOSIT` where
  `MIN_DEPOSIT > 0`) are not recognised as sign checks and are reported; checks on a value derived
  from the parameter, rather than the parameter itself, are not seen. `u128`/`u64` parameters are
  never reported. Amounts inside structs or `Vec`s are not followed.

## Options
