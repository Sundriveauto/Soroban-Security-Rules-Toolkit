# SG-007 — Stored data never has its TTL extended

| | |
|---|---|
| **Name** | `missing-ttl-extension` |
| **Default severity** | info |
| **Confidence** | medium |
| **Tags** | reliability, storage, state-archival |

## What it detects

A contract crate (one with at least one `#[contractimpl]` export) that writes **persistent** or
**instance** storage from its regular functions but never extends the TTL of that tier anywhere in
the crate:

* persistent: no `env.storage().persistent().extend_ttl(..)`;
* instance: no `env.storage().instance().extend_ttl(..)` and no
  `env.deployer().extend_ttl_for_contract_instance(..)`.

Each tier is reported once per crate, at its first write. Writes reachable only from
`__constructor` or an initializer are ignored: one-time configuration is usually kept alive by an
off-chain `ExtendFootprintTTL` operation. Library crates (no contract exports) are skipped because
TTL policy usually belongs to the contract using them. Temporary storage is never reported.

## Why it matters

Persistent and instance entries live until their TTL runs out. They are then archived, and every
invocation that reads them fails until someone submits a restore operation. When the instance is
archived, the whole contract stops working. Contracts that keep changing data (balances, counters,
positions) should extend TTLs on-chain as part of normal use.

## Example

```rust
pub fn award(env: Env, user: Address, points: u32) {
    // …
    env.storage().persistent().set(&DataKey::Points(user), &next);   // ⚠ SG-007
}
```

Fixed:

```rust
const DAY_IN_LEDGERS: u32 = 17280;

pub fn award(env: Env, user: Address, points: u32) {
    // …
    let key = DataKey::Points(user);
    env.storage().persistent().set(&key, &next);
    env.storage().persistent().extend_ttl(&key, 7 * DAY_IN_LEDGERS, 30 * DAY_IN_LEDGERS);
}
```

## Known limitations

* **False positives:** contracts whose operators extend TTLs off-chain on a schedule. Suppress the
  finding with a reason or disable the rule in `stellar-guard.toml`.
* **False negatives:** one `extend_ttl` call anywhere in the crate satisfies the whole tier, even
  if it covers only some keys. Extensions in another crate are not seen.
