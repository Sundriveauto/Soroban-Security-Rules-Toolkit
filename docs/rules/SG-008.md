# SG-008 — Result of a fallible cross-contract call is ignored

| | |
|---|---|
| **Name** | `ignored-try-call` |
| **Default severity** | warning |
| **Confidence** | high (statement), medium (`let _ =`) |
| **Tags** | security, error-handling, cross-contract |

## What it detects

A `try_*` method called on a contract client whose `Result` is thrown away:

* as a statement: `client.try_transfer(&from, &to, &amount);` (high confidence);
* bound to `_`: `let _ = client.try_transfer(&from, &to, &amount);` (medium confidence).

The receiver must look like a contract client: a `*Client::new(..)` value, a local initialized from
one, or a name ending in `client`. `try_` methods of collections and conversions (`try_from`,
`try_into`, `try_get`, `try_update`, …) are not cross-contract calls and are ignored. Results that
are matched, checked with `is_err()` / `is_ok()`, returned or stored are not reported.

## Why it matters

The non-`try_` client method aborts the invocation when the callee fails, so state changes made
before the call are rolled back. The `try_` variant returns the failure instead. If the caller drops
it, execution continues as if the call succeeded: a payout is recorded but the tokens never moved,
a hook is assumed to have run, a refund is marked complete.

## Example

```rust
let _ = client.try_transfer(&env.current_contract_address(), &seller, &amount);   // ⚠ SG-008
env.storage().persistent().set(&DataKey::Paid(seller), &true);
```

Fixed:

```rust
client.transfer(&env.current_contract_address(), &seller, &amount);   // aborts on failure
env.storage().persistent().set(&DataKey::Paid(seller), &true);
```

## Known limitations

* **False positives:** best-effort calls where ignoring failure is the intended design (e.g.
  notifying an untrusted plugin during uninstall). Suppress with
  `// stellar-guard-ignore SG-008 -- <reason>`.
* **False negatives:** results stored in a named variable that is never read, and clients whose
  type and variable names do not mention `client`.
