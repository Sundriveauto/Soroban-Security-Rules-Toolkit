# SG-010 — Privileged changes do not publish an event

| | |
|---|---|
| **Name** | `missing-admin-events` |
| **Default severity** | info |
| **Confidence** | high |
| **Tags** | operations, events, access-control |

## What it detects

An exported contract function that upgrades the contract or writes a privileged storage key without
publishing an event. SG-010 recognizes `env.events().publish(..)` directly or in a helper called by
the exported function. Privileged keys include admin / administrator, owner, operator, minter,
manager, governance / governor, upgrader, pause state, pauser, guardian, authority, treasury,
signer, and WASM keys.

Constructors are not checked: deployment tooling observes constructor state as part of deployment.
This rule checks whether an event is published anywhere in the function's reachable helper calls;
it does not prove that the publication occurs on every path or that its contents describe the
change accurately.

```rust
pub fn set_admin(env: Env, admin: Address) {
    let current: Address = env.storage().instance().get(&DataKey::Admin).unwrap();
    current.require_auth();
    // ⚠ SG-010: the change is not published for off-chain monitoring
    env.storage().instance().set(&DataKey::Admin, &admin);
}
```

Fixed:

```rust
pub fn set_admin(env: Env, admin: Address) {
    let current: Address = env.storage().instance().get(&DataKey::Admin).unwrap();
    current.require_auth();
    env.storage().instance().set(&DataKey::Admin, &admin);
    env.events().publish((symbol_short!("admin"),), admin);
}
```

## Why it matters

Indexers, operators, and monitoring systems commonly rely on contract events to notice admin
changes, pauses, and code upgrades. A state change without a corresponding event is harder to
observe promptly off-chain, even when it is properly authorized.

## Known limitations

* **False positives:** some contracts intentionally rely on transaction or ledger inspection rather
  than events, or publish an equivalent event outside the call chain. Suppress with
  `// stellar-guard-ignore SG-010 -- <reason>`.
* **False negatives:** any reachable `env.events().publish(..)` suppresses the finding, even if it is
  conditional or publishes unrelated data. Events emitted by external crates not resolved in the
  local call graph are not followed.
* The rule recognizes the listed key-name words only; application-specific privileged key names are
  not configurable.
